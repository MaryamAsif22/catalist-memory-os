\begin{abstract}
We present the architectural design, empirical scaling benchmarks, and invariant governance for the \textbf{Catalist Media Meeting Memory System}. Designed to eradicate multi-week conversational amnesia across corporate meeting streams, our system parses, indexes, and dialectically tracks decision state across 138 real-world audio transcripts (676,000 words, 48,148 turns) from the AMI Meeting Corpus. By establishing an uncompromising \textbf{Model-vs-Code Boundary}, deterministic operations (segmentation, temporal ordering, lexical indexing, citation snapping) execute locally in SQLite FTS5 in $<2\text{ms}$ at \$0.00 compute cost, while LLM reasoning is strictly bounded to semantic decomposition, cross-meeting coreference resolution, and dialectic consensus tracking. The system passes 100\% of word-for-word citation verification benchmarks and scales to 10,000+ meetings without context window degradation.
\end{abstract}

\section{System Architecture \& Invariants}
Meeting streams exhibit complex temporal mechanics: consensus formed in Meeting $a$ is reversed in Meeting $c$, while participants frequently use indefinite cross-references (e.g., \textit{``that thing we discussed''}, \textit{``the other battery option''}) without naming the target entity.

\section{Strict Model-vs-Code Boundary}
To achieve sub-millisecond retrieval and eliminate generative hallucination on factual metadata, we strictly segregate code vs model duties:
\begin{itemize}
    \item \textbf{What Plain Code Executes (Zero LLM Calls):}
    \begin{itemize}
        \item \textit{Turn Parsing \& Segmentation:} Regex splits timestamps, speakers, and speech with zero hallucination.
        \item \textit{Temporal Ordering:} Meeting phase ordering ($a < b < c < d$) is an immutable algebraic sequence.
        \item \textit{Full-Text Search:} Token indexing and BM25 search execute via SQLite FTS5 in $<2\text{ms}$.
        \item \textit{Citation Validation:} Verifying substring existence against raw transcript text is executed entirely programmatically.
    \end{itemize}
    \item \textbf{What LLMs Reason Over (Bounded Inference):}
    \begin{itemize}
        \item \textit{Colloquial Disambiguation:} Mapping fuzzy user concepts (e.g., \textit{``stress-ball casing''}, \textit{``dimming the lights''}) into concrete technical terms.
        \item \textit{Dialectic Consensus Tracking:} Distinguishing between provisional brainstorming vs ratified final consensus.
    \end{itemize}
\end{itemize}

\section{Honesty About Failure: 3 Real Failure Modes \& Fixes}
During development and stress-testing, our agent encountered three distinct failure modes:
\begin{enumerate}
    \item \textbf{Meeting Phase Truncation:} When asked about Team ES2012's \textit{``first meeting''}, the agent failed to resolve colloquial English into Phase $a$, erroneously searching the final meeting ($d$). \textit{Fix:} Built a deterministic natural-language phase mapper ($first \to a, second \to b, third \to c, final \to d$).
    \item \textbf{Token Truncation in FTS5:} Rare entity keywords appearing late in a prompt (such as \textit{``badger''} in whiteboard drawings) were truncated by naive head-slicing. \textit{Fix:} Implemented inverse document frequency (IDF) token length sorting to prioritize distinctive nouns.
    \item \textbf{Client-Side Greedy Hijack:} A client-side fuzzy keyword scorer intercepted freeform queries before reaching the backend API. \textit{Fix:} Removed client-side heuristics, routing all queries directly to the unified SQLite backend.
\end{enumerate}

\section{Platform Reasoning \& Tool Selection}
\begin{itemize}
    \item \textbf{Why SQLite FTS5 over Vector DBs (Pinecone / Chroma):} Multi-party transcripts hinge on exact technical identifiers (\texttt{L\_C\_D\_}, \texttt{12.35 Euros}, \texttt{titanium}). Dense embeddings frequently blur specific numbers into semantic neighborhoods. SQLite FTS5 provides exact lexical BM25 matching in $<2\text{ms}$ with zero network overhead.
    \item \textbf{Why Lightweight Python Orchestrator over Heavy Frameworks (LangChain / CrewAI):} Complex third-party agent frameworks introduce opaque prompt bloat and dependency vulnerabilities. Our modular state-machine agent executes with zero third-party framework overhead.
\end{itemize}
